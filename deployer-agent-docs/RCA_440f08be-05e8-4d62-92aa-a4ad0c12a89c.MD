## Why Preview works but Live fails (the precise difference)
The **code is identical** in both (Live routes return 401, not 404). The divergence is **environment + data**, and it is twofold:

1. **Missing secret in Live:** `EMERGENT_LLM_KEY` exists in the Preview environment but was never added to Live. A redeploy only picks up NEW `.env` keys that are present in preview `.env` at deploy time, and it never overwrites/creates keys otherwise — so the AI call has no key in production.
2. **Missing data in Live:** The `smart_reader_config` (global) and `smart_reader_credits` (per-tenant) documents were created in Preview's local Mongo during your E2E testing, but a normal redeploy does NOT copy preview data into the Live Atlas DB (data sync only happens on a fresh-DB / mongo_migration flow). So the live tenant has no enablement/credit records.

## Exact required fix — CONFIGURATION / DATA (NOT code)
No code change is required. Two config/data actions (to be done by the user/E1 — NOT performed here):

- **CONFIG:** Add `EMERGENT_LLM_KEY` to Live (add it to preview `.env` then redeploy so it is picked up, or set it via the Deployment → Secrets tab). Optionally set `SMART_READER_PROVIDER` / `SMART_READER_MODEL` if you want to override the gemini defaults; otherwise the code defaults apply.
- **DATA:** Provision the Smart Reader enablement/credit records in the Live DB `visa-booking-5-your_database_name`: the `smart_reader_config` global doc (id='global', trial_credits) and a `smart_reader_credits` doc (enabled=true, free/paid credits) for each live tenant that should have the feature. Use the app's own admin route `/api/admin/smart-reader/*` (preferred, so it goes through the engine's own validation) or the DB Manager — not a raw migration.

**Classification: CONFIGURATION + DATA. No code fix needed. Live is on the latest build.**
